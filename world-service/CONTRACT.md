# Контракт world-service

Внутренний gRPC-сервис хранения снимков игровых миров. **Не является публичным HTTP API** и в текущей сборке **не проксируется через gateway**.

Источник правды по полям сообщений: [`proto/world/v1/world.proto`](proto/world/v1/world.proto).

---

## Транспорт и адрес

| Параметр | Значение |
|----------|----------|
| Протокол | gRPC поверх **HTTP/2** |
| TLS | По умолчанию **нет** (plaintext / insecure); сервер слушает как задано в `bind_addr` |
| Порт по умолчанию | `:50054` (см. конфиг) |
| Server reflection | Включён (`grpc.reflection.v1alpha.ServerReflection`) — удобно для Postman / `grpcurl list` без импорта `.proto` |

Клиент обязан говорить с сервером как с **gRPC**, а не как с обычным HTTP/1.1 REST.

---

## Авторизация (внутренний сервис)

Поведение задаётся полем **`service_token`** в TOML-конфиге.

| `service_token` | Поведение |
|-----------------|-----------|
| Пустая строка | Проверка **отключена** (только для доверенной сети) |
| Непустое значение | Обязательный секрет в **metadata** входящего вызова |

Поддерживаемые способы передачи секрета (достаточно одного):

- Заголовок gRPC metadata: **`x-service-token: <token>`**
- Или: **`authorization: Bearer <token>`**

Все RPC ниже одинаково проходят через этот перехватчик.

## Сущность `World`

Логическая модель мира (сообщение `World` в proto):

| Поле (proto) | Тип | Смысл |
|--------------|-----|--------|
| `id` | `string` | Уникальный идентификатор (первичный ключ в БД) |
| `name` | `string` | Имя; для **непустых** значений уникально в БД (см. миграцию `worlds_name_unique`) |
| `description` | `string` | Описание |
| `snapshot` | `bytes` | Opaque снимок (например JSON); пустой допустим |
| `schema_version` | `int32` | Версия схемы данных клиента для этого снимка |
| `version` | `int64` | Версия строки для **optimistic locking**; увеличивается при успешной замене снапшота |
| `created_at_unix` | `int64` | Время создания, Unix-секунды UTC |
| `updated_at_unix` | `int64` | Время последнего обновления, Unix-секунды UTC |

В **JSON** (Postman и др.) имена полей обычно в **lowerCamelCase** по правилам protobuf JSON (`schemaVersion`, `createdAtUnix`, …); отдельные клиенты могут отображать иначе.

Поле **`snapshot`** в JSON кодируется как **base64**.

## RPC: `world.v1.WorldService`

### `CreateWorld`

**Запрос:** `id`, `name`, `description`, `snapshot`, `schema_version`.

| Правило | Поведение |
|---------|-----------|
| Пустой `id` | Ошибка `InvalidArgument` |
| `schema_version == 0` (не задан) | Сервис подставляет **1** перед записью |
| Поле `name` | Перед записью обрезаются пробелы по краям (`TrimSpace`) |
| Дубликат `id` | `AlreadyExists` |
| Дубликат непустого `name` (тот же текст, что уже есть у другой строки) | `AlreadyExists` |

**Ответ:** созданный `World` (как в БД после вставки), включая `version == 1` и таймстампы.

---

### `GetWorld`

**Запрос:** `id`.

| Правило | Поведение |
|---------|-----------|
| Пустой `id` | `InvalidArgument` |
| Нет строки | `NotFound` |

**Ответ:** `World`.

---

### `GetWorldByName`

Возвращает мир по **отображаемому имени** (поле `name` в БД). Удобно для сценария «сохранить под именем»: сначала `GetWorldByName`, при `NotFound` — `CreateWorld`, иначе — `ReplaceWorldSnapshot` по `id` из ответа.

**Запрос:** `name`.

| Правило | Поведение |
|---------|-----------|
| Пустой `name` после `TrimSpace` | `InvalidArgument` |
| Нет строки с таким `name` | `NotFound` |

Поиск выполняется по строке **после** `TrimSpace` на сервере; в БД должно быть записано то же нормализованное имя (как при `CreateWorld`).

**Ответ:** `World`.

---

### `ReplaceWorldSnapshot`

Атомарно заменяет **`snapshot`** и **`schema_version`**, инкрементирует **`version`**, обновляет **`updated_at`**.

**Запрос:** `id`, `snapshot`, `schema_version`, `expected_version`.

| `expected_version` | Поведение |
|--------------------|-----------|
| `0` | Проверка текущей версии **не выполняется** |
| Неноль | Обновление только если `version` в БД **равен** этому значению; иначе `Aborted` (несовпадение версии) |

| Правило | Поведение |
|---------|-----------|
| Пустой `id` | `InvalidArgument` |
| Нет мира | `NotFound` |
| Несовпадение версии (см. выше) | `Aborted` |

**Важно:** в отличие от `CreateWorld`, для **`schema_version` нет подстановки по умолчанию**: если передать `0` или опустить поле в JSON, в БД сохранится **0**. Нужное значение нужно задавать явно.

**Ответ:** обновлённый `World`.

---

### `DeleteWorld`

**Запрос:** `id`.

| Правило | Поведение |
|---------|-----------|
| Пустой `id` | `InvalidArgument` |
| Нет строки | `NotFound` |

**Ответ:** пустое сообщение `DeleteWorldResponse`.

---

### `ListWorlds`

**Запрос:** `limit`, `offset`.

| Параметр | Поведение на сервере |
|----------|----------------------|
| `limit <= 0` | Подставляется **50** |
| `limit > 500` | Ограничивается **500** |
| `offset < 0` | Приводится к **0** |

Сортировка: по **`id`** по возрастанию.

**Ответ:** `repeated World worlds` (пустой список — валидный ответ).

## Соответствие ошибок домена и gRPC

Сообщение об ошибке для клиента для `Internal` **не детализируется** (фиксированная строка на стороне маппера).

| Условие | gRPC code |
|---------|-----------|
| Некорректные аргументы (`id` пустой и т.п.) | `InvalidArgument` |
| Сущность не найдена | `NotFound` |
| Мир с таким `id` или непустым `name` уже есть | `AlreadyExists` |
| Optimistic lock: версия не совпала | `Aborted` |
| Прочие ошибки (БД и т.д.) | `Internal` |

## Хранилище (справочно)

Таблица **`worlds`** в PostgreSQL (см. миграции): `id`, `name`, `description`, `snapshot` (BYTEA), `schema_version`, `version`, `created_at`, `updated_at`.

Индекс **`worlds_name_unique`**: уникальность `name` для строк, где `name <> ''` (несколько миров с пустым именем исторически возможны; `GetWorldByName` для пустой строки не используется).

База данных и URL подключения задаются **`database_url`** в конфиге; в Docker см. `deploy/docker/config-world.toml` и корневой `docker-compose.yml`.

| `log_level` | Уровень логов |

## Изменения контракта

Любое изменение полей или RPC должно отражаться в **`proto/world/v1/world.proto`**, затем в этом файле и в сгенерированном коде (`make gen-world` из корня репозитория).
